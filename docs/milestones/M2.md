# M2 · Linux sandbox and the real `galahad scan`

**Status: planned.** M2 is delivered as v0.2.0. The host CLI boots a Firecracker microVM, sends the target into it (a local file or folder, a URL, a Google Drive link, a Git repository or an email), runs `galahad-agent` and the guest tools there, and renders the validated result. No code is written until the definition of done in section 4 is approved.

Scope is the full M2 list in `docs/plan.md` (T2.1–T2.9). Large tasks are split so that each PR has one purpose, which gives 18 cards in 7 waves.

## 1. Architecture

### Key choices
- **The agent is not baked into the image.** The agent binary is attached to the VM as its own read-only drive. Otherwise every commit would change the image hash, and the image hashes pinned in the host binary could never be committed.
- **The guest always dials the host.** The host never connects into the guest and never polls for readiness.
- **Signatures come from an update VM.** `galahad setup` boots a separate VM that downloads the ClamAV and YARA signatures onto a disk. Scan VMs mount that disk read-only.
- **The proxy reads one small JSON frame.** Guest tools talk to a relay inside the guest, which turns their proxy requests into a strict JSON connect frame. The host decodes that frame and then only copies bytes, so it still parses nothing untrusted.
- **One test-only build tag, `galahadtest`.** It enables the fake sandbox backend, the proxy test hooks and the P8 probe. Release builds never set it, and the gate checks that none of this code is linked into a normal build.

### Package layout (new or changed)

internal/sandbox/         Backend, Machine, Spec, Select()

internal/ingest/          guest only: untar, url, drive, git

**Host-safety boundary.** The import check in `scripts/gate.sh` grows: `go list -deps ./cmd/galahad` must not contain `internal/analyze`, `internal/ingest`, `internal/vsock` or `internal/agent`. A second check asserts that a build without tags does not contain `internal/sandbox/fake`.

### Message flow
```
host: galahad scan <target>                             guest VM (no network card)
  classify the target (path / git / drive / url / eml)    /sbin/galahad-init (busybox sh):
  create jobs/<id>, scratch.img (sparse), agent.img         mount proc, sys, dev; mkfs and mount /dev/vdb at /work;
  listen on v.sock_1024 (control), v.sock_1025 (proxy)       mount /dev/vdd (signatures, ro); copy /dev/vdc to /run/galahad-agent;
  boot Firecracker over its API socket                      run the agent, then reboot -f
        <- control: Hello{protocol: 1, agent_version}      the agent dials host port 1024
  check that agent_version equals the host version
        -> Job{id, kind, name, url, submodules, timeouts, now}
  local input: -> Data* (tar stream, 1 MiB chunks) -> End{bytes, sha256}
                                                          ingest into /work/input; each tunnel dials port 1025
        <- Progress{stage}*   (ingest | analyze | clamav | yara | capa | osv)
        <- Artifact{id, bytes}*   (ingest.log, tools.log, probe.json in test builds only)
        <- Result | Error{code, message}                  then the guest closes and reboots
  strict decode, Validate, add Network and GAL-NET-001, scoring.Apply, report.Write, job.json; kill the VM; tear down
proxy (one connection per tunnel on port 1025):
        <- Connect{host, port}   -> ConnectReply{ok, reason}   then raw bytes both ways, relayed and never read
```

### Framing and limits
A frame is a 1-byte type, a 4-byte big-endian length and the payload. The reader checks the length against the limit for that type before it allocates. Frames from the host come only in the order Job, Data*, End. Frames from the guest come only in the order Hello, (Progress | Artifact)*, then Result or Error, then EOF. An unknown type, a frame out of order, an oversize length, or JSON with unknown fields or trailing data is a protocol error: the job fails with exit 1 and the VM is killed.

| Frame | Direction | Max | Payload |
|---|---|---|---|
| Hello | guest to host | 1 KiB | JSON |
| Job | host to guest | 64 KiB | JSON |
| Data | host to guest | 1 MiB | raw tar bytes |
| End | host to guest | 1 KiB | JSON `{bytes, sha256}` |
| Progress | guest to host | 256 B | JSON `{stage}` (enum) |
| Artifact | guest to host | 1 MiB | 1-byte id (fixed enum) and raw bytes; the guest truncates |
| Result | guest to host | 64 MiB | `protocol.Result` JSON |
| Error | guest to host | 4 KiB | JSON `{code, message}`: code is an enum, message ≤ 512 runes, checked like other text |
| Connect, ConnectReply | both | 1 KiB | JSON |

Local input is at most 1 GiB and 200 000 entries. The host checks both while it walks the tree, before streaming. The guest extractor enforces the same caps and refuses absolute paths and `..`.

`Validate` does not cap the length of `files`, `coverage.skipped`, `reasons` or `analyzers` today. T2.2a adds caps at the engine's worst case (files = MaxFiles + MaxExtraFiles = 22 000) and a test that a worst-case Result encodes under 64 MiB.

### vsock ports
Guest CID 3, host CID 2. Port 1024 is the control channel and port 1025 is the egress proxy; the guest dials both. Firecracker maps a guest connection to port P onto the unix socket `<job>/v.sock_P`, so the host only uses unix sockets (`net.Listen("unix")`) and needs no AF_VSOCK code. The guest uses `internal/vsock`. The fake backend uses TCP on `127.0.0.1:0` for both ports, which avoids unix socket path limits on macOS and Windows.

### What the host does with guest data
The host:
1. reads 5-byte frame headers;
2. decodes small fixed-schema JSON (Hello, Progress, Error, Connect, Result) strictly, then runs `Validate`;
3. writes the input tar itself and never reads it back;
4. stores artifacts and the console log as raw capped bytes, never rendered or parsed;
5. relays tunnel bytes without reading them;
6. decompresses release assets (the images and the Firecracker `.tgz`) only after their pinned sha256 matches, with size caps from the pins;
7. reads its own `job.json` and `report.json` back with a strict decode and `Validate`.

For file targets, the host checks `Result.Target.SHA256` against the hash it computed while streaming. `Tool.Version` must equal the host version (a `dev` build skips this). The host re-runs `scoring.Apply`, so the verdict always matches the validated findings.

### Job directory
`~/.galahad/jobs/<id>`, where the ID is the UTC time plus 3 random bytes: `20261021-153012-a1b2c3`. Directories are 0700 and files 0600.
```
job.json          written by the host: id, created_at, finished_at, target {input (cleaned), kind}, image, backend,
                  state (created | booting | running | done | failed | timeout | canceled), exit_code, verdict, score, error, blocked
report.json, summary.md, report.html   rendered by the host from the validated Result
console.log       guest serial console, raw, at most 1 MiB
proxy.log         JSON lines written by the host: time, host, port, ip, decision, reason, bytes up and down; at most 10 000 lines
artifacts/        ingest.log, tools.log (raw guest bytes, at most 1 MiB each, never rendered)
transient         fc.sock, v.sock, v.sock_1024, v.sock_1025, scratch.img, agent.img; removed at teardown
```
If a socket path would exceed 100 bytes, the sockets go under `os.MkdirTemp("", "gh")`. Other state: `~/.galahad/images/<version>/` (vmlinux, core.ext4, re.ext4), `~/.galahad/bin/firecracker` (pinned), and `~/.galahad/signatures.img` (written only by the update VM).

### Sandbox interface
```go
type Spec struct {
	JobDir             string
	Image              string // core | re
	CPUs               int
	MemoryMiB          int
	ScratchMiB         int64
	AgentPath          string
	Signatures         string // "" = none
	SignaturesWritable bool   // update job only
	Ports              []uint32
}

type Backend interface {
	Name() string
	Start(ctx context.Context, s Spec) (Machine, error) // listeners exist before boot
}

type Machine interface {
	Listener(port uint32) net.Listener // guest-to-host connections on that port
	Wait() error                       // returns when the VM or process exits
	Kill() error                       // idempotent: kill, then remove transient files
}

// Select returns the Firecracker backend on Linux and ErrUnsupported ("Linux only until M5")
// elsewhere. In galahadtest builds, GALAHAD_SANDBOX=fake selects the fake backend.
func Select() (Backend, error)
```
`job.Run` applies the timeout by cancelling its context and calling `Kill`. Backends write the console to `console.log`.

### Fake backend (`galahadtest` builds only)
It runs `galahad-agent guest --unsafe-host --control tcp:<addr> --proxy tcp:<addr>`, finding the agent through `$GALAHAD_FAKE_AGENT` or next to `os.Executable()`. `Kill` kills the process, and the agent's stderr goes to `console.log`. It does not enforce CPU or memory limits. The acceptance `TestMain` builds both binaries with `-tags galahadtest`, so every OS runs the full host path: job directory, framing, streaming, proxy, `Validate`, `report.Write` and exit codes.

The tag also enables:
- proxy test overrides: `GALAHAD_TEST_RESOLVE=name=ip,...` (the address block still applies) and `GALAHAD_TEST_SINKHOLE=127.0.0.1:port` (the only loopback address the block lets through);
- plain `http://` for `.test` hosts in Git and Drive ingest;
- the P8 probe job kind.

### Proxy policy (`internal/proxy`)
The allowlist for a job is the union of the rows that apply to it; everything else is denied. The host only ever sees Connect frames. Port 443 is allowed for listed hosts; port 80 only for the host of an `http://` target URL (and, in `galahadtest` builds, for `.test` hosts).

| Hosts | Allowed for |
|---|---|
| the target host (github.com, gitlab.com, bitbucket.org or codeberg.org for Git detection; any host with `--git` or for URL jobs) | Git and URL jobs |
| drive.google.com, drive.usercontent.google.com, docs.google.com | Drive jobs |
| objects.githubusercontent.com, release-assets.githubusercontent.com, raw.githubusercontent.com, codeload.github.com | URL jobs (common redirect targets) |
| api.osv.dev | every scan job, unless `--no-network` |
| database.clamav.net, github.com, objects.githubusercontent.com and release-assets.githubusercontent.com (YARA-Forge release) | the update VM only |
| each `--allow-host h` | that scan |

**DNS is resolved on the host.** The guest has no DNS and sends host names. The block list is checked first, so an IP literal such as 169.254.169.254 is denied with its reason (and becomes `GAL-NET-001`); after that, an IP literal is accepted only when it is the target itself. The host resolves the name with a 5 s timeout, rejects it if any resolved address is not public, and dials the vetted address, so DNS rebinding cannot reach a private address.

**Blocked addresses:**
- IPv4: loopback; RFC 1918; 100.64/10; 169.254/16 (169.254.169.254 gets the reason `metadata`); 0/8; 192.0.0/24; the documentation ranges; 198.18/15; 240/4; multicast; broadcast.
- IPv6: `::`; `::1`; fc00::/7; fe80::/10; ff00::/8; 2001:db8::/32; 2002::/16; IPv4-mapped forms of all the IPv4 ranges; 64:ff9b::/96 with an embedded private address.

**Limits.** 64 concurrent tunnels, 60 s idle timeout, 2 GiB down and 64 MiB up per job. A host name must match `^[a-z0-9.-]{1,253}$` before it is logged.

**Reporting.** The host fills `Result.Network`, aggregated by host, port and decision, with at most 200 entries; a guest that sends `network` itself is rejected. A denial for a private, loopback, link-local or metadata address adds the host finding `GAL-NET-001` (high) with the evidence path `(network)`. The reports get a "Network" section.

### Images
- **Base:** Debian trixie (13), built with `mmdebstrap --variant=minbase` against a pinned snapshot.debian.org timestamp. Debian rather than Alpine, because Alpine drops old package versions (so builds cannot be repeated) and the standalone capa binary needs glibc. Trixie rather than bookworm, because bookworm is in LTS, its mke2fs lacks `SOURCE_DATE_EPOCH` support, and it has no Java 21, which current Ghidra needs.
- **Build:** `images/linux/build.sh` runs in CI inside a `debian:trixie@sha256:<pinned>` container. It is shell only; no Go is involved.
- **Core packages:** ca-certificates, git, clamav, clamav-freshclam, yara, busybox, util-linux (`setpriv`), e2fsprogs (mkfs for the scratch disk inside the guest), unzip.
- **Overlay:**
  - `/sbin/galahad-init`, which brings up `lo` (the relay listens on 127.0.0.1), mounts tmpfs on `/run` and `/tmp` (the root filesystem is read-only), and sets rlimits with `ulimit` before it starts the agent (there is no PAM session, so `limits.conf` would not apply);
  - `/etc/galahad-guest`, the marker `vmguard` already checks;
  - user `galahad` (uid 1000), which the agent drops to after mounting and setting the clock;
  - rlimits: nproc 512, nofile 4096, set by the init script.
- **RE image:** core plus capa (a pinned standalone release, checked against its sha256), Ghidra (a pinned zip) and openjdk-21-jre-headless.
- **Repeatable builds:**
  - `SOURCE_DATE_EPOCH` is the snapshot time;
  - docs, man pages, locales and apt lists are removed, but `/usr/share/doc/*/copyright` is kept;
  - the filesystem is made with `mkfs.ext4 -d rootfs -U <fixed> -E hash_seed=<fixed>,root_owner=0:0` and `E2FSPROGS_FAKE_TIME`.
- **Kernel:**
  - source: a pinned kernel.org 6.1.y tarball;
  - config: `images/linux/kernel/config`, starting from Firecracker's microVM guest config, with no modules, no virtio-net and no 9p or virtiofs, but with virtio-blk, virtio-vsock and ext4;
  - build: `KBUILD_BUILD_TIMESTAMP`, `KBUILD_BUILD_USER` and `KBUILD_BUILD_HOST` fixed, `make vmlinux`.
- **Size targets:**

  | File | Uncompressed | gzip |
  |---|---|---|
  | vmlinux | ≤ 40 MiB | ≤ 15 MiB |
  | core.ext4 | 384 MiB image (≤ 300 MiB content) | ≤ 150 MiB |
  | re.ext4 | ≤ 1.5 GiB | ≤ 700 MiB |

  Assets are gzip because the standard library can read it; zstd or xz would need third-party code.
- **Pins:** `internal/images/pins.json` (embedded) holds:
  - the image release tag (`images-<VERSION>`) and the asset names;
  - the sha256 of each `.gz` and of each decompressed file;
  - the Firecracker version, URL and sha256.

  Because the agent is not in the image, the pins depend only on `images/`. On a PR that touches `images/`, `image.yml` builds the images and fails if the hashes differ from the committed pins, printing the new ones. A green PR therefore shows that two builds matched. Pushing a tag `images-*` rebuilds, compares again and publishes:
  - the assets and `SHA256SUMS`;
  - the provenance attestation;
  - the package manifest;
  - the GPL source packages, and the kernel source tarball and config.

## 2. Task cards (dependency order)

### T2.1 · Job lifecycle, sandbox interface, fake backend
- **Goal:** Job directory and state, the sandbox interface, and a test-only fake backend that runs the agent as a local subprocess.
- **Files:**
  - `internal/config/`, `internal/job/{job.go,store.go}`, `internal/sandbox/{sandbox.go,select.go,select_fake.go}`, `internal/sandbox/fake/`;

- **Acceptance criteria:**

  - `Create` makes a 0700 directory and a `job.json` in state `created`; `Load` decodes strictly.

  - `Select` returns ErrUnsupported on darwin and windows unless the tag and `GALAHAD_SANDBOX=fake` are set.
  - The fake backend's `Start` and `Listener` work against a helper process (a re-exec of the test binary), and `Kill` is idempotent.
- **Rules:** none.
- **Problems:** foundation for P1–P8.
- **QA:** the gate check shows `internal/sandbox/fake` is absent from `go list -deps ./cmd/galahad` without tags; the existing smoke tests pass.
- **Depends on:** none.
- **Size:** L.

### T2.2a · Framing and messages
- **Goal:** Bounded, typed framing and strict decoding for every host and guest message.
- **Files:** `internal/protocol/{frame.go,messages.go,validate.go}` and tests.
- **Acceptance criteria:**
  - Per-type limits are checked before allocation, and there are helpers for the expected order (`Expect(types...)`).
  - `DecodeStrict` uses `DisallowUnknownFields` and rejects trailing data, and every message has a `Validate`.
  - `Validate` gets the new caps on files, skips, reasons and analyzers, and a worst-case Result encodes under 64 MiB.
  - One table case per rejection: oversize, unknown type, unknown field, trailing data, bad enum, control character in `Error.message`.
  - All enums are defined here, up front, so later cards do not edit the protocol for them: job kinds (`scan`, `update`, `probe`, `net-probe`), sources (`local`, `url`, `drive`, `git`), stages, artifact ids, and Error codes (`protocol`, `ingest`, `not_allowed`, `drive_private`, `drive_quota`, `too_large`, `timeout`, `internal`).
  - `Validate` also caps the evidence entries per finding (8), so the worst-case size test holds.
- **Rules:** none.
- **Problems:** P8 (the host never trusts guest bytes).
- **Depends on:** none.
- **Size:** M.

### T2.2b · Agent guest mode with local input
- **Goal:** `galahad-agent guest` dials the host, receives a job and a tar stream, analyzes it, and returns a Result or an Error.
- **Files:** `internal/vsock/` (linux), `internal/ingest/untar.go`, `internal/agent/{guest.go,transport.go}` (`--control vsock:2:1024|tcp:addr`, `--proxy ...`, `--unsafe-host`).
- **Acceptance criteria:**
  - Guest mode refuses to run outside a VM without `--unsafe-host` (the T1.16 rule).
  - The extractor writes through `os.Root`, so it cannot follow a symlink it extracted earlier. It refuses absolute paths, `..`, more than 200 000 entries and more than 1 GiB, and checks `End.sha256`.
  - The analysis timeout is the job timeout minus 60 s, so a timeout skip reaches the host before it kills the VM.
  - A protocol error exits 1.
  - Unit tests drive the guest over `net.Pipe` with a test host written against `protocol`.
- **Problems:** P1–P7.
- **Depends on:** T2.2a.
- **Size:** M.

### T2.2c · Host job runner and `galahad scan <path>`
- **Goal:** Scan a local file or folder end to end through a backend, with the reports rendered on the host.
- **Files:** `internal/job/run.go`, `internal/cli/scan.go`, `test/acceptance/scan_test.go`.
- **Acceptance criteria:**
  - **Walk:** symlinks are not followed (they are sent as tar link entries), and devices and FIFOs are skipped. Input over the caps exits 1 before boot.
  - **Checks on the Result:** the agent version must match, and so must the sha256 for file targets. Then a strict decode, `Validate`, `scoring.Apply` and `report.Write` into the job directory, and `job.json` gets its final state. Artifacts are capped.
  - **Exit and cancel:** the exit code follows the verdict. Ctrl-C (`signal.NotifyContext`) sets the state `canceled`, kills the VM and removes the transient files.
  - Progress stages are printed to stderr.
- **Problems:** P1–P7 (P6: an `.eml` is a local file; its attachments are analyzed as children).
- **QA** (fake backend, all OSes):
  - the M1 corpus table runs through `galahad scan <fixture>` with the same exit codes and evidence;
  - `p6-eml-lure` exits 20;
  - a malformed-Result agent mode (test tag) exits 1 and writes no report.
- **Depends on:** T2.1, T2.2a, T2.2b.
- **Size:** L.

### T2.3 · Firecracker backend
- **Goal:** Boot the guest under Firecracker with CPU, memory, disk and time limits, and tear it down cleanly.
- **Files:** `internal/sandbox/firecracker/{api.go,machine.go,firecracker_other.go}`, `.github/workflows/vm.yml` (KVM udev rule, pinned Firecracker, pinned image download, smoke scans).
- **Acceptance criteria:** API calls over `fc.sock`, in order:
  1. `machine-config`: 2 vCPUs, 3072 MiB, SMT off.
  2. `boot-source`: `console=ttyS0 reboot=k panic=1 pci=off ro root=/dev/vda init=/sbin/galahad-init`.
  3. Drives:
     - `rootfs`, read-only;
     - `scratch`, a sparse 4 GiB file, read-write;
     - `agent`, a copy of the sibling `galahad-agent` padded to 512 bytes;
     - `signatures`, read-only and optional.
  4. `vsock` with CID 3.
  5. `InstanceStart`.

  More criteria:
  - No network interface is configured.
  - The first control connection must arrive within 30 s of boot.
  - `Kill` sends SIGKILL, waits, and removes the scratch disk, the agent image and the sockets.
  - Unit tests use a fake API server on a unix socket and assert the exact request sequence and each error path.
- **QA** (vm.yml on ubuntu-latest):
  - `scan testdata/corpus/benign-go-cli` exits 0 and `p1-folderopen-curl` exits 20;
  - after each run, no firecracker process is left and the job directory holds no transient files.
- **Depends on:** T2.1, T2.2c, T2.5a.
- **Size:** L.

### T2.4a · Host egress proxy
- **Goal:** A policy-enforcing tunnel relay on the proxy port, with host-side DNS, address blocking and a log.
- **Files:** `internal/proxy/{policy.go,proxy.go,block.go,testhooks_fake.go}`.
- **Acceptance criteria:**
  - Each policy rule above has a table case: allowlisted, not listed, wrong port, each blocked range (including IPv4-mapped IPv6), a name that resolves to both public and private addresses, a DNS failure.
  - The proxy dials the vetted address, enforces the caps and the idle timeout, and writes `proxy.log`.
  - Tests use httptest backends and the test hooks.
- **Problems:** P8.
- **Depends on:** T2.2a.
- **Size:** L.

### T2.4b · Guest relay and network reporting
- **Goal:** Guest tools reach the network only through the host proxy, and denials appear in the report.
- **Files:** `internal/agent/relay.go`, `internal/job/run.go` (serve the proxy port with the job's policy), `internal/protocol` (`Network`, `NetEvent`), `internal/report` (Network section), `internal/agent` (a `galahadtest`-only `net-probe` job kind that opens one tunnel to a given host).
- **Acceptance criteria:**
  - The relay listens on 127.0.0.1 (port 3128 in the VM, port 0 with the fake backend so concurrent agents do not collide). It accepts two request forms, because tools use both: `CONNECT host:port` (https) becomes a Connect frame for that host and port; an absolute-form request (`GET http://host[:port]/path`, used for plain http by Go's `http.Transport` and by curl) becomes a Connect frame for that host and port (80 when none is given; the host policy decides), and the relay forwards the request in origin form over the tunnel and closes the client connection after the response, so one keep-alive connection cannot reach a second host. Anything else gets a 400.
  - The guest sets `http_proxy`, `https_proxy`, `HTTP_PROXY` and `HTTPS_PROXY` (curl reads only the lowercase `http_proxy`).
  - The host overwrites `Result.Network`.
  - `GAL-NET-001` evidence path is `(network)`, with a snippet such as `CONNECT 169.254.169.254:443 denied: metadata`.
  - `--no-network` serves no proxy port.
- **Rules:** `GAL-NET-001` high: the input led to a request to a private, loopback, link-local or metadata address.
- **Problems:** P8.
- **QA** (fake backend): a `net-probe` job to `rebind.test` with `GALAHAD_TEST_RESOLVE=rebind.test=10.0.0.1` is denied: `proxy.log` has the denial and the Result carries `GAL-NET-001`. A probe through the relay with both request forms reaches an allowed httptest backend.
- **Depends on:** T2.2c, T2.4a.
- **Size:** M.

### T2.5b · RE image
- **Goal:** An optional image with capa and Ghidra.

  - The size targets are met, and the image is published like core.
- **Depends on:** T2.5a.
- **Size:** M.

### T2.6a · `galahad setup` and `galahad doctor`
- **Goal:** Download and verify the pinned images and Firecracker, and diagnose the host.
- **Files:** `internal/images/`, `internal/cli/{setup.go,doctor.go}`.
- **Acceptance criteria:**
  - **`setup`:**
    - flags `--image core|re` and `--skip-signatures`;
    - downloads over https to a temporary file, stopping at the size in the pins, checks the `.gz` sha256, decompresses with the same size cap, checks the raw sha256, then renames atomically;
    - idempotent: skips a file whose hash already matches;
    - installs Firecracker into `~/.galahad/bin`.
  - **`doctor`:**
    - checks: OS and architecture (linux/amd64); `/dev/kvm` opens read-write (with the kvm group hint if not); Firecracker version; image hashes; sibling agent present and at the same version; at least 5 GiB free; signature age from `~/.galahad/signatures.stamp`, which the host writes after a successful update job (it never reads the guest-written disk) (WARN after 7 days, WARN if missing);
    - prints PASS, WARN or FAIL lines and exits 0 when there is no FAIL, 1 otherwise.
  - **Tests:** unit tests against an httptest asset server cover a hash mismatch (nothing installed), a partial download, and a re-run that does nothing. On darwin and windows, `doctor` FAILs with "Linux only until M5".
- **Depends on:** T2.3, T2.5a.
- **Size:** M.

### T2.6b · Signature update VM
- **Goal:** `setup` fills `signatures.img` through an update VM that never touches a sample.
- **Files:** `internal/agent/update.go` (job kind `update`), `internal/cli/setup.go`, `internal/job` (update policy).
- **Acceptance criteria:**
  - A sparse 1 GiB `signatures.img.new` is attached read-write to this job only.
  - freshclam runs with `DNSDatabaseInfo no` and the proxy settings.
  - The YARA-Forge core release is downloaded and compiled with `yarac` to `/sig/yara/core.yarc`, and a stamp file is written.
  - On success the new image is renamed to `signatures.img`; on failure the old one is kept.
  - Scan jobs attach the image read-only.
- **QA** (vm.yml, cached weekly): after `setup`, `doctor` shows signatures PASS. Then an EICAR file built at test time gives `GAL-SIG-001` and `GAL-AV-001`, and the `benign-*` fixtures still exit 0. This is the first card with signatures, so the VM check of T2.8b runs here.
- **Depends on:** T2.3, T2.4b, T2.6a, T2.8b.
- **Size:** M.

### T2.7a · URL and Google Drive ingest
- **Goal:** Fetch a URL or a public Drive file into the guest through the proxy.
- **Files:** `internal/ingest/{url.go,drive.go}`, `internal/cli/target.go` (classify the target), `--allow-host`.
- **Acceptance criteria:**
  - **URL:**
    - at most 1 GiB, 2 min and 5 redirects; http and https only;
    - the file name comes from `Content-Disposition` or the URL path, cleaned;
    - a redirect to a host that is not allowed ends in the Error `not_allowed`, and the host prints "rerun with `--allow-host <h>`", taking `<h>` from its own proxy record, not from the guest's text.
  - **Drive:**
    - accepts `/file/d/<id>`, `open?id=` and `uc?id=`;
    - downloads from `drive.usercontent.google.com/download?id=..&export=download`;
    - parses the large-file warning page (at most 1 MiB) in the guest with `x/net/html` (hidden `confirm` and `uuid` fields) and resubmits;
    - a redirect to accounts.google.com or a quota page ends in the Error `drive_private` or `drive_quota`.
- **Problems:** P4, P6, P8.
- **QA** (fake backend with test hooks):
  - a URL to `p4-pdf-launch` exits 20;
  - a Drive warning-page fixture leading to `benign-pdf` exits 0;
  - a redirect to 169.254.169.254 is blocked and reported.
- **Depends on:** T2.4b.
- **Size:** L.

### T2.7b · Hardened Git clone
- **Goal:** Clone a repository in the guest so that nothing in it can run.
- **Files:** `internal/ingest/git.go`, `internal/cli/target.go` (the `--git` flag and Git URL detection), `--submodules`.
- **Acceptance criteria:**
  - **Command:**

    ```
    git -c protocol.allow=never -c protocol.https.allow=always -c core.hooksPath=/dev/null -c core.fsmonitor=false \
        -c core.symlinks=false -c filter.lfs.process= -c filter.lfs.smudge= -c transfer.fsckObjects=true \
        -c submodule.recurse=false -c core.askPass=/bin/false \
        clone --depth 1 --no-tags --single-branch --no-recurse-submodules --template= -- <url> /work/input
    ```
  - **Environment:** `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_TERMINAL_PROMPT=0`, `GIT_LFS_SKIP_SMUDGE=1`, `GIT_ALLOW_PROTOCOL=https` (plus `http` for `.test` hosts in `galahadtest` builds), `http_proxy` and `https_proxy` pointing at the relay, and everything else removed. The clone also passes `-c http.proxy=<relay address>` (the relay's actual address, `127.0.0.1:3128` in the VM and a random port with the fake backend), so git has a route even if the environment is changed.
  - **Limits:** 5 min timeout. The size cap is the scratch disk; ENOSPC becomes `too_large`.
  - **Submodules:** `--submodules` runs `submodule update --init --depth 1` with the same settings. A submodule that fails is logged in `ingest.log` and the scan continues.
- **Problems:** P1, P2, P8.
- **QA:** fake backend, with a local git http-backend through `net/http/cgi`. Runs on Linux and macOS; skipped on Windows if git-http-backend is missing.
  - `fake-interview-repo` exits 20 with the same evidence;
  - a repo with a submodule at `https://169.254.169.254/x.git`, scanned with `--submodules`, gives `GAL-NET-001`;
  - `ext::` and `file://` submodules are ignored.
- **Depends on:** T2.4b, T2.7a (which creates `target.go`).
- **Size:** M.

### T2.8a · `report`, `jobs` and scan flags
- **Goal:** Make past jobs usable and complete the scan interface.
- **Files:** `internal/cli/{report.go,jobs.go,scan.go}`.
- **Acceptance criteria:**
  - **`jobs`:** lists ID, state, verdict, score, date and the cleaned target. `jobs rm <id>...` removes jobs.
  - **`report <id>`:** re-reads `report.json` strictly, runs `Validate`, prints the terminal summary and the paths, and exits with the verdict. `report <id> --json` prints the file.
  - **Scan flags:** `--image`, `--timeout`, `--cpus`, `--memory`. (`--no-network` belongs to T2.4b.)
  - **Errors:** an unknown ID exits 1; a malformed ID exits 2.
- **Depends on:** T2.2c.
- **Size:** M.

### T2.8b · ClamAV and YARA in the guest
- **Goal:** Run the signature tools on the input and turn their hits into findings.
- **Files:** `internal/analyze/tools/{tools.go,clamav.go,yara.go}`, `internal/agent/guest.go` (tool step).
- **Acceptance criteria:**
  - **clamscan:** `-r --database=/sig/clamav --infected --no-summary --heuristic-alerts=no --max-filesize=32M --max-scansize=256M --max-recursion=6`, 3 min timeout.
  - **yara:** `-C -N -r -f` with the compiled core rules (`-C` because they are compiled), 2 min timeout.
  - **Paths:** made relative and passed through `CleanPath`.
  - **Missing signatures:** the tool is left out of `coverage.analyzers`, and `tools.log` says why.
  - **Tool timeout or crash:** the tool is left out of `coverage.analyzers` and `tools.log` says why. It is not a `timeout` skip, because the Go engine still covered every file; a missing tool only lowers confidence.
  - **Time budget:** tools share what is left of the job timeout after the engine; each tool's own limit is a ceiling. The scan default timeout is 10 min for `core` and 20 min for `re`.
  - **Parsers:** unit-tested on recorded output, including file names with `: ` and newlines.
  - **Memory:** in guest mode the agent's memory limit defaults to 50% of the VM's RAM, leaving room for clamscan.
- **Rules:** `GAL-AV-001` high: antivirus signature match (signature name in the snippet). `GAL-YARA-001` medium: YARA rule match. EICAR stays `GAL-SIG-001`.
- **Problems:** P5, P7.
- **QA:** the parser tests above, and the fake backend with a stub `clamscan` and `yara` on `PATH` (test tag) that print recorded hits. The real-signature check runs in T2.6b.
- **Depends on:** T2.2c.
- **Size:** M.

### T2.8c · capa and OSV
- **Goal:** Report capabilities of executables (RE image) and dependencies that OSV lists as malicious.
- **Files:** `internal/analyze/tools/{capa.go,osv.go}`, `internal/analyze/static/deps` (export `Pinned(name, data) []Package` for package-lock v2 and v3 and `==` pins in requirements files).
- **Acceptance criteria:**
  - **capa:**
    - runs only with `--image re`, on at most 20 PE, ELF or Mach-O files of at most 32 MiB each, 60 s each and 5 min in total;
    - maps only a fixed set of namespaces (injection, keylogging, credential theft, anti-debugging), and never vm-detection alone.
  - **OSV:**
    - calls `/v1/querybatch` through the proxy, at most 3 requests within 30 s;
    - only `MAL-*` IDs become findings;
    - when offline, the tool is left out of `coverage.analyzers`.
- **Rules:** `GAL-CAPA-001` medium: executable has injection, keylogging, credential-theft or anti-debugging capabilities. `GAL-DEPS-005` critical: dependency is a known malicious package (OSV MAL) (T1195.001).
- **QA:** the built `galahad` binary scanned with `--image re` stays exit 0. An OSV fixture served by an httptest server through the test hooks, returning a MAL entry, exits 20.
- **Depends on:** T2.3, T2.4b, T2.5b, T2.6a, T2.8b.
- **Size:** M.

### T2.9a · P8 isolation suite
- **Goal:** Prove that a compromised guest and hostile inputs stay contained and are reported.
- **Files:** `internal/agent/probe.go` (`galahadtest` only: job kind `probe`, hidden `scan --p8-probe <name>`), `test/acceptance/p8_test.go` (`//go:build vm`), `vm.yml`.

| Probe | Expected on the host |
|---|---|
| fork bomb, memory exhaustion | contained; the host gets a Result or a timeout within `--timeout` |

| sleep forever | state `timeout`, exit 1, nothing left behind |
| oversize Result, unknown-field Result, Result out of order | exit 1, no report, host RSS < 1 GiB |

The probe writes `artifacts/probe.json`; only the test parses it.

## 4. Definition of done for v0.2.0

**Scenarios that must pass**
- **P1–P7.** The full M1 corpus passes through `galahad scan <path>`, on the fake backend (linux, macOS, windows) and on real Firecracker (vm.yml), with the same exit codes and evidence. In addition, `fake-interview-repo` passes through Git ingest and the P4 PDF through URL ingest.
- **P8.** Every T2.9a probe passes.
- **P9, P10.** Out of scope (M3, M4).

**Repos that must stay clean.** Each is scanned through `galahad scan https://github.com/<repo>` with ClamAV, YARA and OSV active.
- These stay CLEAN: cobra, commitlint, eslint, express, fastapi, gin, husky, lodash, requests, ripgrep, golang/tools, vscode-remote-try-node.
- None of the 10 repos that were SUSPICIOUS in v0.1.0 becomes MALICIOUS. Any new reason must be a documented tool hit.
- The built `galahad` binary is CLEAN with `--image re`.

**Known gaps it may ship with**
- Linux amd64 hosts only.
- Static analysis only; Ghidra is installed but not run.
- No jailer: Firecracker runs as the user, with its own seccomp filters.
- URL redirects to other hosts need `--allow-host`.
- Drive: public single files only.
- Git: https only, no `--ref`.
- Links in an `.eml` are listed, not fetched.
- OSV: only `MAL-*` entries, for npm and PyPI pins.
- ClamAV and YARA need the signatures from `setup`.
- No partial Result after a host timeout.
- KVM is tested in CI on one runner type only.

**Manual checklist on the owner's Linux laptop, before tagging**
1. Download the release, check `checksums.txt`, and run `gh attestation verify`.
2. Run `galahad doctor` before setup: it FAILs and names what is missing. Run `galahad setup`, then `doctor`: all PASS.
3. Scan the four target kinds:
   - `scan https://github.com/<you>/fake-interview-repo` gives 20;
   - `scan ./invoice.pdf` (`p4-pdf-openaction-uri`) gives 10;
   - a public Drive link to `benign-pdf` gives 0;
   - an `.eml` (`p6-eml-lure`) gives 20.
4. `scan --submodules <you>/p8-submodule-metadata` shows `GAL-NET-001` in `report.html`.
5. `jobs`, `report <id>` and `jobs rm <id>` work.
6. Ctrl-C during a scan: `pgrep firecracker` is empty, and the job directory holds no `scratch.img` or sockets.
7. With Wi-Fi off, a local scan still works, and OSV is missing from the analyzers list.
8. `~/.galahad` is 0700, and disk use after 10 scans is under 50 MiB.
9. As a user outside the kvm group, `doctor` prints the group hint.
10. A scan of `benign-express-app` takes under 2 min.

## 6. Risks
- **Firecracker on GitHub runners.**
  - ubuntu-latest exposes `/dev/kvm`, but only after a udev rule (`MODE="0666"`). Nested virtualization is slow and sometimes flaky.
  - Mitigations: pin the Firecracker release and its sha256; allow 30 s for boot, with one retry; cache the images; run only on paths that matter: `internal/{sandbox,job,proxy,agent,ingest,protocol}`, `images/`, `cmd/`.
  - `vm` is not a required PR check, but `release.yml` requires it to be green on the tag.
  - The guest clock: it uses kvmclock, and the Job carries `now`. The agent sets the clock when the skew is over 5 min, while it is still root.
- **Image size and release limits.**
  - Each release asset can be at most 2 GiB. The RE image is about 700 MiB gzipped.
  - snapshot.debian.org is slow and rate-limited, so image.yml caches the debs.
  - ext4 output depends on the e2fsprogs version, which the pinned build container fixes.
  - ClamAV needs about 1.2 GiB of RAM to load its database. So the VM gets 3 GiB by default, the agent's memory limit in guest mode is 50% of the VM's RAM (T2.8b changes the guest default from the current 75%), and clamscan runs after the Go engine. T2.8b measures this.
- **Licenses.**
  - The images are separate works distributed next to an Apache-2.0 binary that links none of them.
  - Component licenses:
    - GPL-2.0: ClamAV, git, the kernel;
    - GPL-2.0 with the classpath exception: OpenJDK;
    - BSD-3: YARA;
    - Apache-2.0: capa, Ghidra.
  - For the GPL, the `images-*` release keeps the copyright files and publishes:
    - the package manifest;
    - the source packages (`apt-get source` at the pinned snapshot) of every GPL package in the images, so the sources ship next to the binaries;
    - the kernel source tarball and config.
  - The ClamAV databases and YARA-Forge rules are downloaded by the user's `setup` and never redistributed. The README notes that YARA-Forge rules carry mixed licenses.
- **Google Drive without an API key.** The download flow is undocumented and has changed before: the move to `drive.usercontent.google.com` and the `uuid` form in 2024. It can also return quota pages and login redirects. It stays in one function with fixture tests, each failure maps to a clear Error code, and the manual checklist covers it, so a break costs one small PR.
- **Git clone hardening.**
  - Covered:
    - hooks (`--template=`, `hooksPath`), fsmonitor and LFS filters;
    - the protocol allowlist (`GIT_ALLOW_PROTOCOL=https` blocks `ext::` and `file://`);
    - symlinks off, fsck on, no submodules by default;
    - `--` before the URL, a scrubbed environment, a timeout and the scratch size cap.
  - Remaining risk: a vulnerability in git itself. The image is rebuilt when Debian publishes a git security update, and the clone runs as uid 1000 inside the VM, so a git bug stays in the guest.
  - Submodule hosts must also pass the proxy.
- **Other.**
  - No jailer: a Firecracker escape reaches the user account. Documented, and planned for M7.
  - The host and agent versions can drift apart; the Hello check fails fast.
  - Unix socket paths have a length limit; the short temporary directory handles it.

## Deliberately left out of M2
- **Sandbox:** the jailer and cgroups; snapshots and fast restore; arm64 images; macOS and Windows backends; persistent VMs.
- **Network:** open egress for URL redirects; DNS inside the guest; non-TLS proxying beyond port 80 for the target; a sinkhole (M4).
- **Ingest:** Drive folders and Google Docs export; ssh and `git://` URLs; `--ref` and tree URLs; following `.eml` links; rendering pages with JavaScript.
- **Tools:** Ghidra headless analysis; OSV entries for CVEs (only `MAL-*`); Galahad's own YARA rules; ClamAV PUA and heuristic alerts.
- **Protocol:** progress text (stages only); returning the sample to the host; partial results after a host timeout; the JSON config file (M3).
